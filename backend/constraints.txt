# Exact versions for every Python package CI installs, so a new upstream release
# can't change what the tests run against between one push and the next. Drift has
# caused trouble twice: a security test that silently checked nothing, and
# google-genai 3.0 pulling in httpx2, which changed how the test client sends cookies.
#
# Used as a constraint, so it pins without installing anything by itself:
#     pip install -r requirements-dev.txt -c constraints.txt
#     pip install -r requirements-dev.txt -r requirements-postgres.txt -c constraints.txt
#
# google-genai stays on 2.34.0 on purpose: it's the version in use, and 3.0 is a
# major release nobody has exercised against the real provider. Moving to it is a
# decision for a person. The "newest packages" job in dependency-audit.yml runs the
# suite without this file, so trouble from a newer release shows up there first.
#
# To regenerate, from a clean virtual environment, in backend/:
#     pip install -r requirements-dev.txt -r requirements-postgres.txt google-genai==2.34.0
#     pip freeze | sort -f
